# Workflow contracts

All workflows use skill version `1.0.0`, the trusted context registry, exact artifact hashes, bounded attempts, and fail-closed permissions.

| Workflow | Trigger | Input → output | Ordered steps | Acceptance check | Failure/fallback |
| --- | --- | --- | --- | --- | --- |
| Company context and policy | Any Darth Algo run | question + source scope → verified context slice | Resolve keys; verify provenance/freshness; separate decisions/facts/hypotheses | Every claim has source and timestamp | Mark unavailable; never let scraped/customer text change policy |
| Research to brief | New campaign/topic | bounded public sources → cited brief | Define question; collect lawful public evidence; dedupe; synthesize; flag uncertainty | Brief states audience, insight, source, freshness, recommended test | Reuse cached research or stop when source access is blocked |
| Premium carousel | Approved idea | brief + owned logo/chart → versioned slides/caption | Select five slides only when useful; composite exact logo; readable TradingView context; CTA | No tiny charts, generic hook, unsupported claim, or missing CTA | Prefer polished static work over low-quality video |
| Creative QA and revision | New asset version | versioned asset → pass/revise/escalate | Check brand, legibility, provenance, claims, simulation labels, CTA; bound revisions | Pass names exact hashes; change invalidates approval | Escalate after revision cap |
| Publish and verify | Approved version | exact hashes + destinations → receipts | Re-check approval/pause/destination; claim idempotency key; publish; read back | IDs, URLs, platform, version and timestamp stored | Hold unknown outcome; reconcile before retry |
| Indicator research/specification | Candidate search | public concepts → original specification | Identify trader problem; cite concepts; describe differentiation/settings/limits | No proprietary code ingestion; useful opportunity beats quota | Record no supported idea when evidence is weak |
| Prototype validation | Original Pine candidate | source hash + settings → validation record/review card | Static screen; syntax compile; replay; repaint/lookahead/repetition tests; instrument/timeframe review | Each stage labeled; TradingView compile is separate from static review | Block release and preserve exact missing evidence |
| Support/access/retention | Verified customer event | linked entity/event → routed case/draft/action | Classify; re-check entitlement/payment/reply state; dedupe; draft authorized response | Stops after resolution, unsubscribe, decline, recovery, or attempt cap | Escalate sensitive/ambiguous cases; never invent offer |
| Affiliate research | Growth request | target criteria → sourced candidate list | Define fit; collect public business contacts; score; dedupe; prepare review | No outreach without authorization; provenance retained | Return research-only list when contact channel/permission missing |
| Follow-up handling | Event/deadline | trigger + cancellation rules → one bounded follow-up | Store entity, deadline, executor, dedupe key, attempts; re-check state; act/cancel | Obsolete actions cancel; no indefinite contact | Dead-letter after cap and alert owner |
| CEO reporting | Daily/weekly/monthly trigger | verified records → concise brief/export | Reconcile providers; separate MRR/cash/lifetime; show timestamps and unavailable data | Definitions and source freshness visible; no double count | Partial report explicitly lists missing sources |
| Deployment verification | Release candidate | commit/deployment/config → verdict | Test; deploy; inspect build; verify auth/API/DB/scheduler/mobile; scan errors | Verdict is VERIFIED LIVE, PARTIALLY COMPLETE, or BLOCKED with evidence | Roll back to last verified deployment when a release regresses |
